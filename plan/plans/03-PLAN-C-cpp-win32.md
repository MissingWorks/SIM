# Plan C (غير مُفضلة) — C++ + Win32 / WinUI 3

**المتى تُفتح:** فقط إذا فرض المستخدم C++ لأسباب خارجة عن التخطيط الحالي.

**الفكرة:** تطبيق Win32 خالص (+ C++/WinRT لـ WinUI 3 للواجهات، أو Win32 كلاسيكي لكل شيء).

## الإيجابيات

- أقصى تحكم وأقل حجم واعتماديات وقت تشغيل.
- لا أي طبقة وسيطة — كل شيء مباشر مع النظام.
- معرفة عميقة مطلوبة أقل من Rust في مرحلة "البحث عن حلول جاهزة" (مصادر Win32 أكثر).

## السلبيات (أسباب الترتيب الثالث)

1. **أمان الذاكرة:** عملية طويلة العمر تتعامل مع بيانات المستخدم → احتمال Use-After-Free/تسريبات أعلى بكثير.
2. **إدارة المكتبات:** vcpkg/CMake أكثر هشاشة؛ المستخدم طلب صراحة الاعتماد على مكتبات جاهزة مجرّبة — Cargo يحقق هذا أسهل بكثير.
3. **سرعة التطوير:** بناء UI عربي جيد في WinUI 3 معقد (تدفق XAML + ساعات عمل أكثر).
4. **التوظيف/الصيانة المستقبلية:** أصعب.

## لو استُخدمت — توزيع المهام المقترح

| الطبقة | التقنية |
|---|---|
| المحرك (التقاط/تخزين/إعدادات) | C++20 + WIL + SQLite (المكتبة الرسمية) |
| الواجهة | WinUI 3 (C++/WinRT) — وهي الوحيدة التي تدعم العربية جيدًا في هذا المسار |
| Tray | Win32 Shell_NotifyIcon |
| الاختصارات | RegisterHotKey |
| التخزين | sqlite3 مباشر |
| JSON/TOML | nlohmann/json + toml11 |

## المراحل (مختصرة — نفس منطق Plan A)

0. تجارب: قراءة الحافظة الخام (AddClipboardFormatListener + تنسيقات)، WinUI 3 spike للعربية، RegisterHotKey.
1. هيكل المشروع (CMake + vcpkg) + Tray + نافذة إعدادات مبدئية.
2. محرك الالتقاط (نصوص) + SQLite + اختبارات.
3. الصور (DIB/PNG + مصغرات).
4. لوحة Quick Panel (نافذة Win32 بلا إطار قرب الصينية).
5. اللوحات المتعددة + اختصاراتها.
6. الإعدادات الكاملة + عربي/إنجليزي.
7. تصليب + Soak.
8. تغليف (WiX/Inno Setup).

**ملاحظة أمانة:** هذه الخطة أدنى جودة تطويرية في هذا المشروع، وشُملت اعترافًا بحق المقارنة، لا توصية.
