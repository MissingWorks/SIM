# Plan A (المعتمدة) — Rust + Tauri v2

**الهدف:** مدير حافظة احترافي (v1) داخل حزمة SIM — إنجليزي أساسًا وعربي اختياريًا — محلي بالكامل، يعمل 24/7.

**التقنية:** `sim-core` (Rust) + `sim-desktop` (Tauri v2 + HTML/CSS/JS بسيط) + `sim-cli` (أداة تطوير).

**المرجع المعماري:** كل التفاصيل البرمجية الملزمة (بنية الملفات، واجهة EngineHandle، الـ DDL، التوقيتات، التدفقات) في `../ARCHITECTURE.md`. هذه الخطة تحدد *ماذا ومتى وكمخرج*، والمعمارية تحدد *كيف*.

**التقدير الزمني الإجمالي:** 6–8 أسابيع عمل مركّز لـ v1 (تقديري — يعاد تقييمه بعد المرحلة 0) + 3–4 أسابيع للميزة الثانية (المراحل 9–11).

# المرحلة 1 — هيكل المشروع + Tray + نافذة إعدادات مبدئية

**الهدف:** تطبيق يقلع، يعيش في الصينية، يفتح نافذة إعدادات — الأساس الذي يُركب عليه كل شيء.

**المهام البرمجية (بالترتيب):**

1. **Workspace:**
   - `code/Cargo.toml`: workspace بـ members الثلاثة + `[workspace.dependencies]` مركزية للنسخ.
   - `code/rust-toolchain.toml`: تثبيت قناة مستقرة.
   - كل crate بـ `Cargo.toml` الخاص (Core بلا Tauri إطلاقًا — هذا يفرض الفصل).
2. **Core — الإعدادات (config.rs):**
   - `struct Config` كاملًا طبقًا لمخطط ARCHITECTURE + `Default` = القيم الافتراضية الموثقة.
   - `load(path) -> (Config, LoadReport)`: ملف غير موجود → افتراضي؛ تالف → rename إلى `config.bad-<ts>.toml` + افتراضي + Report يظهر للمستخدم.
   - `save()` ذري: temp + rename (ويندوز: استخدام `replace_file` أو fallback rename مع إزالة مسبقة — يُختبر).
   - `validate()`: حدود (slots ≤ 20، القيم الموجبة، إلخ) — أي قيمة خارج الحد تُصحح وتُسجل.
3. **Core — الأخطاء (error.rs):** `CoreError` بـ thiserror مع تصنيف Transient/Degradable/Fatal (ARCHITECTURE).
4. **Core — السجلات:** تهيئة tracing في القشرة → `logs/sim.log` دوّار يوميًا (tracing-appender) — يوفرها Core كدالة `init_logging(dir)`.
5. **القشرة — Tray (tray.rs):**
   - أيقونة مؤقتة + قائمة يمين: Settings / Pause capture (toggle) / Quit.
   - نقرة يسار = toggle اللوحة (في هذه المرحلة: نافذة فارغة كما هي الشاشة الحالية — تُستبدل في المرحلة 4).
6. **القشرة — النوافذ:** `settings` (900×640) تُفتح من القائمة أو بوسيط `--settings`؛ `panel` هيكل فقط (جاهز للمرحلة 4).
7. **single-instance:** التسجيل مع callback → إظهار نافذة الإعدادات في النسخة القائمة (show ثم set_focus — التركيز يفشل على نافذة مخفية، Tauri #12936).
8. **autostart:** تفعيل/تعطيل من stub الإعدادات + انعكاس الحالة الفعلية من الريجستري عند الإقلاع.
9. **CLI أولي:** `sim-cli config get <key> | set <key> <value> | path` — يثبت أن Core يعمل مستقلاً.

**اختبارات:**
- وحدة: config round-trip، ملف تالف، validate يرفض القيم الشاذة.
- يدوي: سيناريوهات DoD أدناه.

**معايير الخروج (DoD):**
- [ ] التطبيق يقلع Tray-only ولا يظهر في شريط المهام
- [ ] تشغيل نسخة ثانية لا يكرر العملية بل يفتح Settings في القائمة
- [ ] config.toml يُنشأ افتراضيًا ويصمد عبر إعادة التشغيل
- [ ] autostart: تفعيل → تشغيل فعلي عند إعادة تشغيل ويندوز (تجربة واحدة حقيقية)
- [ ] خروج من القائمة نظيف (لا عمليات معلقة في Task Manager)
- [ ] `cargo clippy -- -D warnings` نظيف + `cargo-deny check` ناجح

# المرحلة 2 — محرك الالتقاط: نصوص + تخزين + استبقاء

**الهدف:** كل نسخة نصية تُلتقط وتُخزن وتُدار — عبر CLI فقط بدون واجهة.

**المهام البرمجية:**

1. **منصة (platform/window.rs):** إنشاء نافذة رسائل (HWND_MESSAGE) + حلقة رسائل على خيط مخصص — مغلفة في `MessageWindow::create(handler)`.
2. **المستمع (clipboard/listener.rs):**
   - `AddClipboardFormatListener` + معالجة `WM_CLIPBOARDUPDATE`: أولًا تجاهل الرسائل الزائفة بمقارنة `GetClipboardSequenceNumber` مع آخر رقم مُعالج (D21/U27 — أدوات النظام تطلق تحديثات بلا تغيّر) → ثم `CaptureSignal { seq: u32 }` عبر `capture_tx` (bounded 256 — عند الامتلاء: تجاهل إشارة (لا نحجب نظام الرسائل أبدًا) مع تسجيل).
   - إزالة المستمع عند الإغلاق.
3. **القارئ (clipboard/reader.rs):**
   - فتح بـ retry (10 × 10ms — قابلة للرفع حتى 10×100ms بنمط .NET الرسمي إن أثبت Spike-6 الحاجة؛ البارامترات النهائية منه؛ عند استمرار الفشل سجّل `GetOpenClipboardWindow` للتشخيص).
   - فحص المالك (نتجاهل أنفسنا) — يحتاج تسجيل HWND نافذتنا من القشرة إلى Core (`EngineHandle::set_own_hwnd` أو يُنشئ المستمع نافذته ويمرر معرفها).
   - `is_excluded_format_set()` — الثلاثة أعلام (U02).
   - قراءة نص: CF_UNICODETEXT → تطبيع للبصمة (CRLF→LF) — **النص يخزن كما هو**.
   - `owning_process_name()` — لاستبعاد التطبيقات (يُستعمل لاحقًا).
4. **المخزن (store/):**
   - `schema.rs`: DDL الكامل من ARCHITECTURE + migrations عبر `user_version` (v1 الآن فقط).
   - `StoreActor`: خيط يملك `Connection`؛ يستقبل `StoreCommand` enum؛ يرد بـ crossbeam oneshot؛ يعمم `Event`s.
   - `queries.rs`: `insert_clip`, `list`, `get`, `delete`, `clear`, `pin`, `stats`, `storage_bytes`.
   - `blobs.rs`: كتابة/حذف ملف blob (يُفعّل فعليًا في المرحلة 3).
5. **الاستبقاء (retention):** الخوارزمية حرفيًا كما في ARCHITECTURE (داخل معاملة الإدراج).
6. **المحرك (engine.rs):** `Engine::start` يُقلع: config → DB → actor → listener → يعيد `EngineHandle`؛ كل المنهجيات تنفذ dispatch بزمن أقصى 2s.
7. **CLI:** `list [--kind text] [--limit N]`, `watch` (يطبع كل إضافة/حذف مباشرة), `pause/resume`, `clear --unpinned`.

**اختبارات:**
- وحدة (بلا ويندوز): استبقاء (أضف max_items+10 → العدد الحالي = الحد، الأقدم حُذف، المثبت نجا)، تطبيع البصمة، validate.
- تكامل (على ويندوز): نسخ 20 نصًا متنوعًا → list يعيدها بالترتيب؛ نسخ نفس النص مرتين → عنصر واحد؛ `watch` يطبع < 10ms.
- إجهاد: سكربت Spike-6 يعاد تشغيله مقابل الإنتاج الفعلي.
- تكامل: تشغيل أدوات نظام/فتح برامج بلا نسخ فعلي → صفر عناصر وهمية (U27).

**معايير الخروج (DoD):**
- [ ] نسخ نص عربي/إيموجي/كود → يظهر في `list` خلال < 10ms p95 (يُقاس بالسجل)
- [ ] تكرار متتالٍ لا يُنشئ عنصرين؛ تغيّر seq أثناء القراءة لا يفسد شيئًا
- [ ] تجاوز الحدود يُخلي الأقدم غير المثبت تلقائيًا
- [ ] قتل مفاجئ للعملية 10 مرات → `PRAGMA integrity_check` سليم في كل مرة
- [ ] نسخ من Bitwarden (بعلاماته) **لا يدخل** السجل (إثبات بـ watch)
- [ ] U10 يُغلق بالدليل

# المرحلة 3 — الصور + نظام اللصق (Paste Subsystem)

**الهدف:** الصور كاملة الجودة + أول تسليم قيمة للمستخدم: Enter يلصق في النافذة الصحيحة. (لا واجهة بعد — الوضع auto يُختبر من CLI مؤقتًا: `paste-last --mode auto`.)

**المهام البرمجية:**

1. **فك DIB (image_util.rs):**
   - قراءة CF_DIBV5 → CF_DIB عبر clipboard-win `get_bitmap()`.
   - `dib_to_bmp_buffer()`: إضافة BITMAPFILEHEADER (14B) → `image::load_from_memory` → `DynamicImage` → PNG موحد.
   - المسار السريع: إن وُجد PNG مسجل (المتصفحات/لقطات حديثة) — استخدامه مباشرة بلا فك/إعادة ترميز.
2. **المصغرة:** `imageops::thumbnail` بعرض 64px (للقائمة) — تُخزن حيث تقرر U18 (مبدئيًا: عمود blob إن صغيرة).
3. **سياسة التخزين:** 96KB عتبة → BLOB أو ملف `blobs/ab/{hash}.png` (مجلدان مقسمان بالبادئة الأولى).
4. **`max_item_bytes`:** ما فوقه يُتجاهل بهدوء مسجل — وقيد صريح: لا فك للصورة قبل فحص الحجم الخام (نمنع تفجير الذاكرة).
5. **نظام اللصق (paste.rs):** التسلسل حرفيًا من ARCHITECTURE — مع سلسلة ضمان المقدمة D20 (SetForegroundWindow → خدعة ALT مرة واحدة → نسخ فقط + إشعار؛ **AttachThreadInput ممنوع**)؛ عند فشل الكتابة للحافظة: إعادة محاولة + تسجيل `GetOpenClipboardWindow` (تشخيص CLIPBRD_E_CANT_OPEN).
6. **كاتب الحافظة (clipboard/writer.rs):** نص/PNG/قائمة ملفات (`raw::set`) + عدم وضع أعلام استبعاد (نحن المصدر المقصود).
7. **CLI:** `paste-last [--copy-only]`, `paste-slot <n>`.

**اختبارات:**
- وحدة: DIB→PNG على صور مرجعية (16/24/32-bit)، مصغرة بالنسب الصحيحة، رفض > max_item_bytes.
- تكامل: Snipping Tool، Copy Image من Chrome/Firefox، Paint، صورة 8K كبيرة.
- لصق: المصفوفة السبعة من Spike-7 تعاد على الكود الفعلي.

**معايير الخروج (DoD):**
- [ ] الصور من المصادر الثلاثة تُخزن وتُلصق بجودة كاملة (مقارنة بصرية + تطابق بصمة البرمجية)
- [ ] حذف عنصر يحذف ملفه المرافق فعليًا (فحص المجلد)
- [ ] لصق في Notepad/Chrome/VSCode/Word ينجح بزمن إجمالي < 1s من Enter إلى ظهور النص
- [ ] نافذة admin → fallback نظيف برسالة مفهومة (لا تجمد ولا خطأ صامت)
- [ ] U08 يُغلق بالتوثيق + U09 تُعالج أو تُوثق مع قرار
- [ ] مع الإعداد الافتراضي على Win10+ (القفل معطِّل فعليًا للرفع المبرمج): اللصق ينجح بفضل سلسلة D20 أو يسقط لـ fallback نظيف — موثق بالأرقام (U28)

# المرحلة 4 — لوحة الاستخدام (Quick Panel)

**الهدف:** الواجهة اليومية: فتح فوري، بحث، كيبورد كامل، لصق بضغطة.

**المهام البرمجية:**

1. **نافذة اللوحة:** إعدادات tauri.conf الحرفية من ARCHITECTURE + ربط positioner (تمرير on_tray_event إلزامي) + إخفاء عند Blur + Esc + **حارس نقرة Tray** (لا وميض إظهار/إخفاء عند النقر خلال ~250ms من الإخفاء — Tauri #8869؛ القيمة تُضبط في Spike-2/U04) + **استعادة تركيز WebView2** عند Focused(true) عبر setFocus (وإلا الكيبورد ميت بعد Alt-Tab — D22).
2. **جسر IPC (bridge.rs):** أحداث Core → `clip-added` / `clips-changed` للواجهة (مع throttling: أحداث متتالية < 100ms تدمج).
3. **الواجهة (panel/):**
   - قائمة العناصر: نوع + معاينة (سطران) + وقت نسبي + حجم؛ الصور: مصغرة؛ الملفات: أيقونة + الأسماء.
   - قرار U18: تجربة الخيارين واعتماد الأسرع لرسم 50 مصغرة.
   - بحث فوري (debounce 120ms) → `clips_list {search}`.
   - فلاتر: الكل/نص/صورة/ملفات/مثبتة (أزرار أعلى اللوحة).
   - كيبورد: أسهم، Enter (paste_mode من الإعدادات)، Ctrl+Enter (copy-only دائمًا)، Ctrl+P مثبت، Delete، Esc، وأرقام 1..9 لنقل العنصر المحدد إلى لوحة (المرحلة 5).
   - شريط سفلي: العدادات (عدد/حجم) + Pause toggle + زر Settings (يفتح نافذة الإعدادات).
   - صفر نصوص hardcoded — كل شيء من `i18n/en.json` حتى في هذه المرحلة (ar.json يُملأ المرحلة 6).
4. **ربط اللصق:** استدعاء `paste_clip(id, mode)` + استقبال `PasteFallback` → toast صغير داخل اللوحة "Copied — press Ctrl+V to paste".
5. **الأداء:** قياس زمن الفتح (ميزانية < 150ms) وقياس رسم القائمة — توثيق الأرقام.

**معايير الخروج (DoD):**
- [ ] نسخ → اختصار → Enter → النص في التطبيق الصحيح (ثلاث تطبيقات مختلفة)
- [ ] كل العمليات بلا ماوس: فتح، تصفح، بحث، لصق، إغلاق
- [ ] زمن الفتح < 150ms (p95 على جهاز التطوير — توثيق الرقم)
- [ ] 50 مصغرة تُرسم < 300ms إحساس بصري (قالب رقمي: زمن الرد في الـ console)
- [ ] اللوحة لا تظهر في Alt+Tab ولا في شريط المهام
- [ ] Blur يخفيها فورًا (تجربة مع نافذتين)
- [ ] بحث في 10k عنصر < 50ms (يُقاس)
- [ ] U12 تُقاس وتحل على شاشتين/مقياسين — أو بديل موثق
- [ ] نقرة Tray سريعة أثناء الإخفاء: لا وميض ولا نافذة عالقة (حارس D22) + الكيبورد يعمل فورًا بعد Alt-Tab (استعادة تركيز WebView2 موثقة)

# المرحلة 5 — اللوحات المتعددة (Slots)

**الهدف:** "حافظات بعدد تحدده" — ميزة التفرد الحقيقية (The Register: لا منافس يوفرها بشكل نظيف).

**المهام البرمجية:**

1. **النموذج (Core):** عمود `slot` موجود من البداية (المرحلة 2) — الآن:
   - `move_to_slot(ids, slot)` + `slot_counts()` + منطق سقف اللوحة (نفس `max_items` يوزع: كل لوحة مستقلة بسقفها = max_items، لكن السقف الكلي للحجم واحد).
   - `paste_slot(n, mode)` = أحدث عنصر غير مثبت في اللوحة n → لصق.
   - حذف لوحة (عند تقليص العدد): اختيار المستخدم (نقل عناصرها → الرئيسية أو حذفها) — الحوار يظهر في الإعدادات.
2. **الاختصارات:** `Win+Alt+1..9` مرتبطة بـ `paste_slot` مباشرة (تسجيل/إلغاء مركزي من hotkeys.rs).
3. **الواجهة:**
   - تبويبات صغيرة أسفل فتحة البحث: Main + أسماء اللوحات (A..E افتراضيًا).
   - الأرقام 1..9 على العنصر المحدد = نقله للوحة المقابلة (مع Toast "Moved to B").
   - قائمة سياق على العنصر (زر يمين): Copy / Paste / Move to ▸ / Pin / Delete.
4. **الإعدادات في نفس المرحلة (استثناء مبكر):** عدد اللوحات + أسماء (واجهة مبسطة داخل نافذة الإعدادات — يكتمل باقي المركز في المرحلة 6).

**اختبارات:** سيناريو Data-flow: 3 عناصر → 3 لوحات → كل اختصار يلصق الصحيح؛ تقليص العدد مع عناصر في اللوحة المحذوفة (كلا الخيارين)؛ إعادة التشغيل — البيانات في مكانها.

**معايير الخروج (DoD):**
- [ ] 9 اختصارات لصق تعمل بدقة (سيناريو كامل موثق)
- [ ] تقليص/زيادة العدد لا يفقد بيانات بلا قرار مستخدم صريح
- [ ] عنصران بنفس النص في لوحتين مختلفتين = عنصران مستقلان (لا دمج بين اللوحات)
- [ ] استعلام لوحة واحدة لا يقرأ القاعدة كلها (فحص EXPLAIN QUERY PLAN يستخدم فهرس slot)

# المرحلة 6 — مركز التحكم (الإعدادات الكاملة + en/ar)

**الهدف:** الواجهة الرسمية من قائمة ابدأ: كل إعداد له واجهة، كل نص مترجم.

**المهام البرمجية:**

1. **هيكل الإعدادات (settings/):** ستة أقسام من ARCHITECTURE — كل حقل مرتبط مباشرة بعقدة config via أوامر `config_get/set` (لا نموذج منفصل يُزامن — مصدر واحد).
2. **تطبيق فوري:** كل تغيير → `set_config` → validate → حفظ ذري → `ConfigChanged` → القطع التي تتأثر تعيد التهيئة (اختصارات تُسجل من جديد، لوحات تُبنى، إلخ) — اختبار "تغيير كل إعداد دون إعادة تشغيل".
3. **ثبات واجهات الاستبعاد:** قائمة `excluded_apps` مع منتقي عمليات (قراءة العمليات النشطة عبر windows-rs وتنقية قائمة).
4. **التقاط اختصار (Hotkey capture):** حقل ضغط عليه = يلتقط المفاتيح (JS keydown → تحويل إلى صيغة الإضافة) → محاولة تسجيل → نجاح/تعارض مع سبب.
5. **الترجمة:** تعبئة `ar.json` كاملًا + مبدل لغة + `dir=rtl` + مراجعة بصرية RTL (حواف، أرقام، تواريخ نسبية) — وتشغيل فحص "لا نصوص hardcoded" (سكربت grep صغير).
6. **اختصار Start Menu:** زر "Create Start Menu shortcut" ينشئ `.lnk` في `%APPDATA%\Microsoft\Windows\Start Menu\Programs` (عبر COM IShellLink أو shorcut crate إضافي — يُقرر عند التنفيذ بـ "لا نكتب من الصفر": نبحث مكتبة، أرجح: `mslnk` أو COM عبر windows-rs).
7. **النسخ الاحتياطي:** زر Export DB → `VACUUM INTO` لمسارات blobs الملفية في ZIP (خوارزمية بسيطة)؛ زر Import مع تحقق النسخة.
8. **عن التطبيق:** النسخة، رابط المستودع، التراخيص (NOTICE)، زر فتح مجلد البيانات.

**معايير الخروج (DoD):**
- [ ] لا يوجد إعداد يُعدل يدويًا في الملفات — 100% عبر الواجهة
- [ ] تغيير: اللغة/الثيم/الاختصارات/اللوحات/حدود التخزين/الاستبعاد — فوري بلا إعادة تشغيل، ويصمد بعدها
- [ ] سكربت فحص النصوص hardcoded = صفر نتيجة
- [ ] RTL: جولة بصرية موثقة (لقطات) على اللوحة + الإعدادات بالعربية
- [ ] اختصار Start Menu يعمل على حساب ويندوز نظيف
- [ ] Export/Import: نسخة تعيد كل شيء على تركيب نظيف (تجربة فعلية)

# المرحلة 7 — التصليب (Hardening)

**الهدف:** إغلاق كل بنود UNVERIFIED الباقية، والانتقال من "تعمل" إلى "مضمونة".

**المهام:**

1. مطاردة البنود: U03 (سياسة العنصر العابر لكلمات المرور)، U09 (تلوث الطرفية)، U11 (Soak 72 ساعة)، U15 (المراجعة إن بقي Plan A — تُغلق كغير مطبقة)، متبقي U12/U18 إن بقي شيء.
2. حالات حدية إلزامية (كل واحدة اختبار مكتوب):
   - قتل العملية أثناء كتابة صورة كبيرة (20 مرة متتالية) → integrity_check سليم
   - قرص ممتلئ (ملء تجريبي) → رسالة واضحة + عدم فساد قاعدة
   - قاعدة بحجم السقف بالضبط → الإخلاء يتصرف بلا حلقة لا نهائية
   - شاشة مقلوبة/عمودية + تغيير القياس أثناء فتح اللوحة
   - 3 نسخ في نفس الميلي ثانية (سكربت)
   - تشغيل متزامن مع Clipboard History (Win+V) ومدير حافظة آخر ليوم كامل → لا ازدواج ولا فساد (موسّع لـ U27)
3. تدقيق أخطاء صامتة: تجعيد `Result` غير معالج (بحث كود: `let _ =` في مسارات مهمة تُراجع واحدة واحدة).
4. مراجعة أمنية: تأكيد صفر شبكة (فحص شجرة تبعيات نهائي بـ cargo-deny + Netstat أثناء تشغيل أسبوع كامل)، السجلات نظيفة (فحص محتوى ملف logs فعلي)، بلوبات لا تحتوي مسارات شخصية في الأسماء (hash فقط ✓).
5. توثيق المستخدم المبدئي (FAQ تشغيلي داخلي — يُصقل في المرحلة 8).

**معايير الخروج (DoD):**

- [ ] كل الحالات الحدية مرّت موثقة النتائج

# المرحلة 8 — التغليف والتوزيع

**الهدف:** منتج يُثبت بملف واحد ويعمل من أول تشغيل.

**المهام:**

2. **البناء:** `tauri build` → bundle NSIS. فحص حجم الحزمة وتقليله (release profile: lto, opt-level, strip — تُضبط وتُوثق).

4. **WebView2 (U17):** ضبط خيار التضمين في المُثبّت (bootstrapper بلا إنترنت → download) + تجربة على Win10 نظيف.
5. **التراخيص:** NOTICE نهائي + تدقيق U13 (clipboard-win حسم نهائي) + ترخيص مشروعنا (D9 المحسوم).
6. **اختبار التثبيت الكامل:** VM نظيف → تثبيت → كل شيء يعمل → إلغاء تثبيت → البقايا = صفر (فحص يدوي موثق).
7. **وثائق المستخدم:** README مستخدم (كيفية + FAQ + الخصوصية بأسطر صريحة) + ملاحظات الإصدار.

**معايير الخروج (DoD):**
