# Spike-3 — bench تخزين SQLite (المرحلة 0)

**الغرض:** حسم U07 + D5 — مقارنة «BLOB داخل القاعدة» مقابل «ملفات على القرص» لـ1000 صورة (50KB–5MB، إجمالي ~2.6GB) بنفس PRAGMAs المعتمدة، مع Defender real-time فعّال.
**الحالة:** ✅ مكتمل 2026-10-18 — الأرقام الكاملة في `../../../plan/plans/phase0-results.md` (قسم Spike-3)، والدليل الخام في `spike3-log.txt`.

## البناء والتشغيل

1. `cargo build --release`
2. `run-bench.cmd` — يشغّل الأداة؛ تكتب `spike3-log.txt` مباشرة.
3. الناتج: `spike3-data/` (قواعد + مجلد blobs — مؤقتة، غير مرفوعة).

## النتيجة المختصرة

- العتبة 96KB مؤكدة: الملفات أسرع للصور الكبيرة (إدراج 2.2×، قراءة 2–3×، عرض مصغرات 6.6×).
- `incremental_vacuum` لا يسترجع الصفحات المتبعثرة داخل القاعدة → VACUUM دوري في خطة الاستبقاء.
- قائمة 50 نص من 10k = 0.16ms — LIKE كافٍ على هذا المقياس.

> مجلد تجربة مؤقت — لا يدخل الإصدار (يُؤرشف/يُحذف عند إغلاق المرحلة 0).
